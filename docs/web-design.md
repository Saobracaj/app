# Веб-версия: макет и как он лёг на приложение

Макет: проект Claude Design «Дизайн веб-версии Saobracaj»
(`d1596677-20e0-436d-9661-8efcaa1b03d8`, файл `Saobracaj Web.dc.html`, превью
1440×900). Ниже — результат сверки макета с текущей вёрсткой и темой и то, во
что он превратился в коде.

## Сверка токенов: расхождений нет

Токены `:root` в макете — это ровно тот же Material 3-палитра, что генерит
приложение из своего сида по умолчанию (`kDefaultSeedColor` = `Colors.blue`,
`ColorScheme.fromSeed`). Проверено дампом схемы:

| Макет | Значение (светлая / тёмная) | Токен `ColorScheme` |
|---|---|---|
| `--primary` | `#36618e` / `#a0cafd` | `primary` |
| `--onprimary` | `#ffffff` / `#003258` | `onPrimary` |
| `--pc` / `--onpc` | `#d1e4ff` `#194975` (инверсно в тёмной) | `primaryContainer` / `onPrimaryContainer` |
| `--secc` / `--onsecc` | `#d7e3f7` `#3b4858` | `secondaryContainer` / `onSecondaryContainer` |
| `--surface` | `#f8f9ff` / `#111418` | `surface` |
| `--sclow` | `#f2f3fa` / `#191c20` | `surfaceContainerLow` |
| `--sc` | `#eceef4` / `#1d2024` | `surfaceContainer` |
| `--schigh` | `#e6e8ee` / `#272a2f` | `surfaceContainerHigh` |
| `--schighest` | `#e1e2e8` / `#32353a` | `surfaceContainerHighest` |
| `--on` / `--onvar` | `#191c20` `#43474e` | `onSurface` / `onSurfaceVariant` |
| `--outline` / `--ov` | `#73777f` `#c3c7cf` | `outline` / `outlineVariant` |

Отсюда правило: **в коде не появляется ни одного хардкод-цвета из макета** —
везде стоят токены схемы. Семантические цвета макета (`--correct`, `--wrong`,
`--warn`, `--info` и их контейнеры) — это `QuizColors` (`theme/quiz_colors.dart`).

Два места, где макет и схема расходятся, и что с ними сделано:

* `--bg` (`#eef0f3`) — полотно страницы, чуть темнее карточек. Ближайший токен
  `surfaceContainer` (`#eceef4`), он и используется (`widePageBackground`).
  Разница — единицы в каждом канале, глазом не различима.
* Акцент. Макет нарисован от фиксированного `#36618e`, а приложение сидит на
  выбранном пользователем акценте (и на Android 12+ — на динамической палитре
  обоев). Менять это ради макета не стали: сид по умолчанию как раз даёт
  палитру макета, а прочие акценты остаются рабочими, потому что цвета берутся
  из схемы, а не из констант.

Шрифт совпадает: макет просит Inter, приложение уже на Inter
(`kAppFontFamily`, зашит в ассеты). Типографика макета (26/22/17/15/14/13 px)
разложена по ролям `TextTheme` (`headlineSmall` / `titleLarge` / `titleMedium` /
`titleSmall` / `bodyMedium` / `bodySmall`) с `fontWeight: w600` у заголовков —
пиксель в пиксель не совпадает, но иерархия та же, а размеры остаются
масштабируемыми системными настройками.

## Что реализовано

Всё ниже включается только на широких окнах и не трогает телефонную вёрстку.
Брейкпоинты прежние (`core/responsive.dart`): `expanded` = 840, `large` = 1200.

* **`core/presentation/wide_layout.dart`** — общий каркас: `WideContent`
  (колонка контента до 1240 с отступами 40), `PageHeading`, `SectionHeading`,
  `SurfaceCard`, `ResponsiveGrid` (аналог `repeat(auto-fill, minmax(N, 1fr))`),
  `MainWithSide`, `StatTile`.
* **`core/presentation/app_sidebar.dart`** — боковая колонка 244 с логотипом,
  подписанными разделами и блоком аккаунта с переключателем темы. Заменяет
  развёрнутый `NavigationRail` при ширине ≥1200; на 600–1200 остаётся компактный
  rail, ниже 600 — нижняя панель.
* **Главная** — заголовок с подзаголовком, списки вопросов сеткой (minmax 232),
  группы сеткой (minmax 340) с карточкой-приглашением «Создать группу».
* **Вопросы** — закреплённая шапка с поиском, подкатегории плитками
  (minmax 400) с обложкой, счётчиком и мини-гистограммой; ссылка на конспект в
  заголовке категории.
* **Настройки прогона** — карточка переключателей плюс карточка-стартер с
  числом вопросов и кнопкой.
* **Результат прогона** — крупный итог «N из M верно», три плитки-счётчика,
  список ошибок карточкой, действия строкой.
* **Симуляция экзамена** — настройки и таблица прошлых попыток (статус, баллы,
  ошибки, время, когда) слева, карточка запуска с порогом и лучшим результатом
  справа.
* **Настройки** — колонка разделов слева, панель аккаунта справа.
* **Конспект** — закреплённое содержание слева, текст в читаемой колонке справа.

Экран вопроса уже был двухколоночным (`_WideQuestBody` в `test/quest/quest.dart`)
и в макет укладывается — его не переделывали.

## Чего в реализации нет

* Горячих клавиш (`/`, `←/→`, `1–4`) — в макете они есть в подсказке боковой
  колонки, в приложении не реализованы; сама подсказка поэтому не выводится.
* Выбора акцентного цвета кружками и вкладки «Внешний вид» прямо в правой
  панели настроек — оформление по-прежнему отдельный экран (`/appearance`).
* Мастер-детали в настройках: разделы открываются отдельными страницами, а не
  подменяют правую панель.

## Как проверять в браузере

```bash
flutter build web --release --no-tree-shake-icons --target lib/main_prod.dart
# отдать build/web любым SPA-сервером (фолбэк на index.html) и открыть 1440×900
```

Подробности про puppeteer-прогон — в заметке `app-web-browser-testing`.

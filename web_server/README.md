# saobracaj_web — сервер веб-версии (saobracaj.gleb.at)

Маленький сервер на Rust (axum), который раздаёт сборку `flutter build web`.
Обычного статического сервера здесь не хватает по трём причинам:

1. **Диплинки.** `https://saobracaj.gleb.at/invite/ABC-DEF-GHI` — не файл на
   диске. Любой неизвестный путь отдаёт `index.html` с кодом 200, иначе
   приглашение открывалось бы 404-й страницей.
2. **Превью ссылок.** Мессенджеры и соцсети не запускают Flutter — они читают
   `<head>`. Сервер подставляет в `index.html` заголовок, описание и Open
   Graph-теги той страницы, которую попросили: для `/question/:id` — текст
   самого вопроса и его картинку (берутся из `assets/assets/allQuestions*.json`
   в самой же сборке, дублировать ничего не надо), для `/invite/:token` —
   нейтральную карточку без кода приглашения.
3. **Проверка ссылок платформами.** `/.well-known/assetlinks.json` (Android App
   Links) и `/.well-known/apple-app-site-association` (iOS Universal Links)
   вшиты в бинарник и отдаются с `Content-Type: application/json` — Apple файл
   без расширения, статический сервер угадал бы тип неверно.

4. **Кэш, который сбрасывается деплоем.** Имена файлов у `flutter build web` не
   содержат хэша содержимого: `main.dart.js` и `assets/assets/allQuestions.json`
   называются одинаково во всех релизах, и по URL браузер не отличит вчерашнюю
   копию от сегодняшней. Поэтому весь бандл отдаётся с `Cache-Control: no-cache`
   («спроси меня», а не «не храни»), а на старте сервер считает отпечаток
   каждого файла и отвечает на эту проверку `ETag`-ом: неизменившийся файл —
   304 в несколько сот байт, изменившийся деплоем — сразу новое тело. Новая
   версия доходит до пользователя на первой же перезагрузке, ждать TTL не надо.
   Исключение — картинки вопросов (`/assets/assets/img/**`): их ~1500, они
   адресуются по id вопроса и от релиза к релизу не меняются, так что у них
   остаётся настоящее окно кэша (сутки).

5. **Индексация поисковиками.** Приложение компилируется в WebAssembly и
   рисует себя на канвасе: краулер, запросивший `/question/7921`, получает
   `<head>`, бутстрап-скрипт и ни одного слова. Google исполняет JS, но и в
   отрендеренном DOM индексировать нечего — текст внутри канваса. Поэтому
   сервер кладёт содержимое страницы прямо в HTML (`src/seo.rs`), отдаёт
   `robots.txt` и `sitemap.xml` (`src/sitemap.rs`) и помечает `noindex`
   всё личное и платное. Подробности — ниже.

Плюс мелочи, на которых веб-сборка спотыкается: `application/wasm` для
`.wasm`, gzip/brotli, `nosniff`, аккуратная 404 для запроса несуществующего
ассета (иначе HTML попал бы в кэш service worker под именем картинки).

## Индексация: что именно отдаётся поисковику

Содержимое страницы пишется в сам HTML, перед `</body>`, в блок
`<div id="seo-prerender">`. Это **не** отдельная версия для роботов: блок
получают все, никакого user-agent-сниффинга (это было бы клоакинг). Для
человека он — то, что заполняет экран, пока грузится бандл; приложение
убирает блок из DOM по событию `flutter-first-frame`. Если JS выключен или
бандл не загрузился, содержимое просто остаётся на месте.

Что попадает в индекс и откуда берётся (всё — из самого бандла, ходить в
бэкенд не нужно):

| Адрес | Содержимое | Источник |
|---|---|---|
| `/question/:id` | текст вопроса, иллюстрация, варианты с пометкой правильного, категория, ссылки на соседние вопросы блока | `assets/assets/allQuestions*.json` |
| `/questions` | каталог: категории → области → ссылки на вопросы | `categories.json` |
| `/zakon` | оглавление закона по главам и статьям | `parsed_zakon.json` |
| `/zakon?chapter=..&chlan=N` | текст статьи, соседние статьи | `parsed_zakon.json` |
| `/konspekt?category=25\|26\|28` | области категории и её вопросы | `categories.json` |
| `/`, `/practice`, `/about`, `/tariffs` | описание и навигация | — |

Плюс `application/ld+json` в `<head>`: `Quiz`/`Question` с правильным ответом
для вопроса, `BreadcrumbList`, `Article` для статьи закона, `WebSite` для
главной.

**Что не отдаётся.** Правило то же, что в приложении и на бэкенде
(`questions::FREE_CATEGORY_IDS`): бесплатны сами вопросы и закон, а переводы,
конспекты, объяснения и анализ — только в категориях 25/26/28. Поэтому у
платной категории вопрос предрендерится **по-сербски даже для читателя с
`Accept-Language: ru`** (иначе через краулер утекал бы весь русский банк), а
конспект платной категории получает `noindex` и не предрендерится вовсе.
Личные экраны (аккаунт, группы, списки, чат, приглашение, прогон теста)
закрыты и в `robots.txt`, и мета-тегом `noindex, follow`.

**Канонический адрес.** Один экран — один адрес: `/konspekt/question/11` и
`/question/11?chat=1` канонизируются в `/question/11`, `/home` и
`/index.html` — в `/`. В query остаются только параметры, меняющие
содержимое (`chapter`, `chlan`, `category`).

**Язык.** Один адрес обслуживает три языка по `Accept-Language`, поэтому
ответ помечен `Vary: Accept-Language`, а в индекс попадает сербская версия
(краулеры заголовок не шлют). Отдельные адреса на язык (`/ru/...`) —
отдельная задача: это правки роутинга в самом приложении.

**Объяснения и обсуждения вопросов** живут в базе бэкенда, а не в бандле,
и закрыты фича-флагами (`ask_ai` — premium, `public_question_comments` —
authenticated; обсуждение теперь чат, `chatFor(QUESTION)`). Чтобы их
индексировать, нужен публичный read-путь на бэкенде и решение владельца, что
именно открывать; сервер к этому готов — добавляется ещё одна ветка в `seo.rs`.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `WEB_ROOT` | `/srv/web` | каталог со сборкой (`build/web`) |
| `HOST` / `PORT` | `0.0.0.0` / `8080` | адрес прослушивания |
| `PUBLIC_ORIGIN` | `https://saobracaj.gleb.at` | origin для `og:url` и `canonical` |
| `CROSS_ORIGIN_ISOLATION` | `off` | `off` / `credentialless` / `require-corp` |
| `RUST_LOG` | `info` | уровень логов |

### Про `CROSS_ORIGIN_ISOLATION`

Изоляция (`COOP: same-origin` + `COEP`) включает `SharedArrayBuffer`: это
многопоточный рендерер Skia и самый быстрый OPFS-режим drift. Она же ломает
попап входа через Firebase (его убивает именно `COOP: same-origin`) и любые
сторонние ресурсы без CORP/CORS-заголовков. Поэтому по умолчанию **выключена**:
drift сам откатывается на более медленный, но рабочий режим хранения, а
соц-логин продолжает работать. Включать — осознанно и с проверкой входа
Google/Apple в вебе.

## Локальный запуск

```bash
cd app
flutter build web --wasm --release          # можно и обычный flutter build web
cd web_server
WEB_ROOT=../build/web PORT=8080 cargo run

open http://127.0.0.1:8080
curl -s http://127.0.0.1:8080/question/7935 -H 'Accept-Language: ru' | grep og:
```

Проверить, что видит поисковик:

```bash
curl -s http://127.0.0.1:8080/question/7921 | grep -A20 seo-prerender
curl -s http://127.0.0.1:8080/robots.txt
curl -s http://127.0.0.1:8080/sitemap.xml | grep -c "<loc>"   # ~1950 адресов
```

Тесты: `cargo test` (60 тестов — маршрутизация, заголовки, подстановка мета-тегов,
разбор файлов вопросов и закона, предрендер и его гейты, robots/sitemap,
содержимое `.well-known`).

## Как это собирается и деплоится

`app/Dockerfile` собирает этот крейт и кладёт рядом уже готовый `build/web` —
Flutter внутри образа не запускается (это +2 ГБ и минуты на каждый деплой).
Джобы `build-web` / `deploy-web` общего пайплайна
`.github/workflows/build-and-deploy.yml` (см. `docs/ci-cd.md`) при пуше в `main`:

1. `flutter analyze`, `flutter test`, `cargo test`;
2. `flutter build web --wasm --release --target lib/main_prod.dart`;
3. сборка образа `ghcr.io/saobracaj/saobracaj_web` и пуш в GHCR;
4. по SSH на OVH VPS: `WEB_IMAGE=<тег>` в `~/app/.env`, `docker compose pull web`,
   `docker compose up -d web`.

Сервис `web`, TLS и nginx описаны в `saobracaj_backend/deploy` (там же
инструкция по DNS и сертификату) — веб живёт на той же машине, что и API.
